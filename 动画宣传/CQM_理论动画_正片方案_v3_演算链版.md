# CQM 理论动画：正片方案 v3.0（演算链版 · 每部 ≥10 分钟）

> **缘起**：对话判定四点——(一) 90 秒太短，至少 10 分钟，节奏参考 Claude 科普动画；(二) 现有动画「偏离理论、反映不了理论、纯空洞」；(三) 要有动画声音，**不要文案解说声**；(四) 参考只取 2026-10～11，9 月的落后作废。
> **本文件只做设计，不进入制作。** 制作按 §八 门禁逐部放行。
> **接管关系**：v1.0（9 章 682 s）、v2.0（15 章 1500 s）由本文件接管——两者的**章目、判据、三层音效、状态双编码、措辞 lint 全部继承**，体裁与结构按本文件重排。
> **定位**：制作方案，不是理论文档。CQM 的主张、数值、缺口状态一律以 `01`–`07` 原文与 `08` 组织层为准。

## 一、诊断：现在的动画为什么空洞

| # | 症状 | 根因 |
|:--|:---|:---|
| 1 | 画面上是「环节」不是「演算」 | 观众看到「晶胞量子振荡 → 不确定性 → 跃迁谱 → 资格条件 → 本征值交叉」，但**看不到其中任何一步是怎么算出来的**。箭头链是工序图，不是推导。 |
| 2 | 每个镜头都好看，但看完整片说不出「CQM 算出了什么」 | 全片没有一次**从公理或定义出发、连续三步以上、算到数值结论**的完整演算。 |
| 3 | 「有镜头意识」但「没有理论」 | 视觉语法借自 Claude 科普动画，**内容却只有环节**；工序图画得再准，也只是把「只有环节」这件事拍了一遍。 |

**关键判断**：症状 1 与 3 的根因**不在动画侧，在文档侧**——`01`–`07` 里相当一部分公式本来就「只有环节没有具体推导链路」。动画只能照抄，于是必然空洞。

⟹ **v3.0 的第一原则**

$$\boxed{\ \text{上屏公式白名单} \;\equiv\; \text{文档审计后「有推导链路」的公式集}\ }$$

文档侧清掉的「只有环节」的公式，动画侧**一律不上镜**；若清掉后某章失去可演算内容，该章结论**降级为「待推」**并同步缺口状态。**动画与文档共用同一份白名单**，这是反空洞的结构性保证，不是靠"再打磨"。

### 2.3 时长从哪来：「不注水」的操作化定义

时长**由演算步数决定，不由章节数决定**。新增的每一秒必须对应至少一个可见中间量：

| 动作 | 最短节拍 | 依据 |
|:---|:--:|:---|
| 一个中间量落定（写 → 算 → 落框 → 静止） | 1.2 s | 静止 0.4 s 是让观众读完的最低量 |
| 一次代入（原式亮起 → 逐项替换 → 化简 → 结果） | 2.5 s | 代入是演算链最小可播单元 |
| 一个数字逐位落定 | 0.5 s / 位 | 逐位 tick，与音效事件表同拍 |
| 章节转场 | 1.5 s | 底床换频，**不做空镜** |

**演算容量校验（示例，第 11 章）**：$10\times10$ 矩阵 $M=E^{T}E$ 的特征多项式 $|\lambda I-M|$ 是 10 阶，展开有 11 个系数项；3 个根各需代回 $10\times10$ 矩阵验证，合计 ≥30 次代入点算。仅此一项即需 ≥75 s 的纯演算时间——**第 11–13 章的 720 s 由演算步数自然撑起，不需要注水**。

### 2.4 节奏参考（Claude 科普动画的时间尺度）

Claude 科普片的可播单元是「**单机制片 3–5 分钟**」（一次缩放、一次锁定、一次求根）。v3.0 取其**时间尺度**而非其总长：

- 一个「机制段」= 3–5 分钟 = 一次从零演算走到底；
- 一部正片 11–12 分钟 = 2–4 个机制段 + 1 次贯穿；
- **成片节奏的单位是「一次演算」，不是「一个镜头」**。

## 三、质量核心：「演算链上镜」原则

### 3.1 公式三态（缺一不上镜）

每个上屏公式必须在片源里挂三样东西：

| 挂件 | 内容 | 机检字段 |
|:---|:---|:---|
| **锚点** | 上游依据：公理／定义／已证结论（写明出处章节） | `anchor` |
| **演算** | 至少一步可见推导动作：代入／展开／求解／求根／取极限／计数／配平 | `derivation` |
| **落定** | 结果 + 状态徽章（金环／青三角／琥珀断环／白方框／紫虚线） | `badge` |

`anchor`/`derivation`/`badge` 任一缺失 → **该式不上镜**。

### 3.2 五条硬门禁

| # | 门禁 | 判定 | 状态 |
|:--|:---|:---|:--|
| G1 | **演算覆盖率 100%** | 片中公式数 = 有 `derivation` 的公式数 | 机检 |
| G2 | **每部 ≥3 处从零演算** | 每处连续 ≥3 个中间量，从公理/定义到数值结论 | 人检 |
| G3 | **白名单一致** | 上屏公式全部在 §六 的白名单内 | 机检 |
| G4 | **数字双通道** | 每个数字要么当场算出，要么标「原文给定」+ 出处章节 | 人检 |
| G5 | **徽章不是内容** | 待推/缺口处必须有可见标记，且旁注「已知到哪一步、缺的是哪一步」 | 人检 |

### 3.3 三条禁止

1. **禁止环节图开场**：每部开头 15 s 必须是**一次真实演算**，不是一条箭头链的全景。
2. **禁止用「于是」跳步**：从上一式到下一式之间的每个中间量都要上屏；算不动的地方标「此处不可算」并给理由，**不许用动画跳过**。
3. **禁止「漂亮但空」**：任何 3 s 内没有可指认对象、没有数值在变、没有状态变化的镜头，删。

### 3.4 与 v2.0「不注水」量化约束的关系

v2.0 §二 的「≥4 可指认对象 / ≥1 可见运算 / ≥8 处 10 位有效数字」继续有效，但**权重倒置**：v2.0 允许一章只有 1 次运算（其余靠对象数凑），v3.0 追加 G2（每部 ≥3 处从零演算）。**对象数不再能替代演算。**

## 四、声音：动画声音，不要文案解说声

### 4.1 口径（继承，不变）

**三层程序化音效，无人声、无配乐、无鼓点、无 riser。**

| 层 | 频段 | 增益 | 职责 | 触发 |
|:---|:---|:--:|:---|:---|
| 底床 bed | 40–120 Hz + 粉噪（低通 400 Hz） | −32 dB | 维持「同一世界」的连续感 | 全程 |
| 结构音 structure | 220–1400 Hz | −24 dB | 把**数值**变成音高 | 数值变化 |
| 事件音 event | 60–3000 Hz | −18 dB | 标记**突变** | 入场、取到、塌陷、落框 |

**「不要文案解说声」的准确含义**（沿用章 06 时刻表的澄清）：分镜表里的 narration 列是**屏上文字**，**不是配音**；全片不出现人声，含 TTS、含气息。

### 4.2 两条新增映射（为「演算上镜」服务）

| 视觉量 | 声音规则 | 参数 |
|:---|:---|:---|
| **演算行写入** | 每写入一行给一个 tick，**音高按行的作用分三档**：锚点行低、 中间量中、结果行高 | 锚点 220 Hz／中间 330 Hz／结果 440 Hz，40 ms，指数衰减 τ=12 ms |
| **一次代入** | 短促带通噪声（"替换"感），与普通 tick 区分 | 1.2–2.6 kHz 带通，120 ms，−24 dB |

⟹ **不看画面也能听出「这行是中间量还是结果」**；这是「关掉声音画面成立、打开声音信息多一层」的可检验版本。

### 4.3 补一项可复现性缺口

当前成片音轨（`.workbuddy/tmp/audio.m4a`）**没有生成脚本**，成片不可复现；片源 HTML 内也没有任何 Web Audio 代码。

**v3.0 起**：音频生成脚本随片源入库于 `动画宣传/工具/audio_gen.mjs`——
输入 = 事件表 JSON（沿用章 06 的 `03_音效事件表.md` 表格结构）；
输出 = 48 kHz 立体声 WAV（母带 −16 LUFS，真峰 ≤ −1 dBTP）；
编码 = ffmpeg AAC-LC 192 kbps。
脚本**只允许正弦与带通白噪**（无锯齿波、无 TTS 调用）——「无人声」由脚本结构保证，而非靠人自觉。

### 4.4 底床换频（段落标记，唯一允许的段落信号）

I 幕 55 Hz → II 幕 49 Hz → III 幕 41.2 Hz → IV 幕 43.6 Hz → V 幕 36.7 Hz。**下行＝下潜**，与「层级深度」同向。换频时静默 0.3 s 再回，**不用 riser**。

## 六、与文档侧的联动：一份白名单，两个消费者

### 6.1 流程

```
文档公式审计（判定：有推导链路 / 仅环节 / 断链 / 定义式）
        │
        ├──→ 白名单（定义式 + 有推导链路）──→ 动画上屏清单
        │
        └──→ 删除清单（仅环节 + 断链）──────→ 文档修订（删除或降级为「待推」）
                                                   │
                                                   └──→ 缺口状态、Lean 覆盖、组织层全链同步
```

### 6.2 联动纪律

| 规则 | 内容 |
|:---|:---|
| **同源** | 白名单由文档审计产出，动画**不得**自行判定某式「够格上镜」 |
| **同步** | 文档删式 ⟹ 动画必须在同一版本内把该式从片源移除，并重跑 `事实核查矩阵` |
| **降级连带** | 若删式后该章无可演算内容 ⟹ 该章**结论降级为「待推」**，缺口状态同步下调（**只许下调，不许上调**） |
| **新增列** | `事实核查矩阵` 增列「推导链路」（锚点 / 演算动作 / 可上镜） |

### 6.3 本轮审计的初步结论（超导侧）

超导侧是「只有环节」的**重灾区**（审计清单见本次会话报告），典型：

- §11.1 的 $\Delta\delta_v(T)=\Delta\delta_0\sqrt{1/(1+2n_B)}$：tanh **恒等式**是真推导，但「涨落幅度 ∝ 1/√(1+2n_B)」这一步在正文中**未被推出**；
- §11.10 的 $V_{\text{角亏激活}}=\frac{\beta^2\Delta\delta_v^2(n^2-1)}{4n^2(1-\beta\delta_v)}$：「激活＝方差」是断言；
- §11.10 的映射 $\Phi(L_{\text{orbital}})=V_{\text{角亏激活}}$：断言式映射；
- §12.1／§12.2 的两条因果链：环间无可见推导。

⟹ **第 14 章《超导》若按现状制作，必然是「环节图」**。它要么等文档侧把超导的演算链补出来，要么就**暂缓**——不得用画面精度掩盖内容缺失。

## 七、制作路线

### 7.1 先演算样片，再铺正片

每部开拍前先做 **90 s 演算验证段**：从一部里挑**一次完整演算**（G2 口径），从零算到底，作为该部的「母版演算」。验收不通过 ⟹ 该部不开拍。

**理由**：v2.0 的「先做 P1」的逻辑正确但不够——P1 验证的是「这一章好不好看」，v3.0 要验证的是「**这一章算不算得出来**」。

### 7.2 批次

| 批 | 内容 | 时长 | 帧数 @60fps | 产物 |
|:--|:---|--:|--:|:---|
| V0 | 五部各一段 90 s 演算验证段 | 450 s | 27,000 | 五段母版演算 |
| V1 | 部三 全片（$G_N$ 那条链最硬） | 720 s | 43,200 | 《从角亏到 $G_N$》 |

### 7.3 渲染纪律（继承）

- 单文件 HTML 片源 + Edge headless CDP 逐帧渲染（工具须**入库**，不再放 `.workbuddy/tmp`）；
