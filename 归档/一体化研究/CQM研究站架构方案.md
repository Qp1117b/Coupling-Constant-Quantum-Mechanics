# CQM 研究站 · 架构方案（对标 + 冗余清理 + 三档路线）

> **文档定位**：本方案只讨论**站点与组织层的架构、冗余清理与技术路线**，不修改、不引申、不评价任何 CQM 物理结论。
> 它接续 `一体化研究/组织层对标与完善方案.md`（那份管 V/P/R/B 工程条目），本文件管**站级架构**。
>
> **三条不可让渡的约束**（本方案所有取舍都从它们出发）：
> 1. **离线红线**：面向读者的产物必须 `file://` 双击即用、零外链资源；
> 2. **单一源与三条红线**：不欺骗／不绕过／不虚构，数据唯一源仍是 `01_结构化数据/*.csv` 与 `01`–`07` 原文；
> 3. **git 原生**：项目是 git 仓库，站点的"版本历史"由 git 承担，不需要另建一套版本/权限系统。

---

## 0. 结论先说

- **站已经成型，缺的不是重构而是"归类 + 清理 + 一处升级"**：阅读站（Material）作为唯一入口的格局刚合并完成，四件可视化已内嵌；接下来做三件事——**按 Divio 四象限重组导航**、**删掉 4 类冗余**、**把"操作"象限的两个空位补上**（证据复核工作台、复现指南）。
- **"Spring Boot 级别"这件事，建议走"混合渐进"而不是直接上服务端**：静态站保持默认与离线，**另加一个可选本地服务**提供实时 SPARQL、实时检索与复核写回；站点自动探测服务在不在，不在就退回现在的行为。理由见 §4。
- **不需要引入的**：协作编辑、权限系统、多用户、云端托管、CDN、任何生成模型。

## 1. 对标：三类"类似玩意"分别能借什么

### 1.1 形式化/数学项目的官网（最贴近的一类）

- **mathlib 的文档总览**（来源 [1]）采用 **Divio 文档系统**的四象限：**教程**（Tutorial，学习导向）／**操作指南**（How-to，问题导向）／**解释**（Explanation，理解导向）／**参考**（Reference，信息导向），并给每篇文档打领域与难度元数据。它的组织单位不是"目录"，而是"**读者要做什么**"。
- **nLab / Stacks Project**（来源 [1][2]）是 wiki 形态，强项是超链接密度与"术语即条目"；但它们是多人协作社区，需要 wiki 的编辑与权限层。
- **Lean 蓝图系**（来源 [3]）把"陈述 ↔ 代码 ↔ 依赖图 ↔ 进度色"四者绑在一条线上——这正是我们缺口台账与蓝图要做的事。

**可借**：①Divio 四象限直接作为本站信息架构；②"术语即条目"（我们已有 82 个概念卡，可以升级为完整条目页）；③陈述↔代码↔进度色（我们的缺口台账 + 蓝图）。

### 1.2 自托管知识平台（能力清单很全，但要甄别）

对比了 BookStack、Wiki.js、Docmost、XWiki、DokuWiki、MediaWiki、Typemill 等（来源 [4][5]），它们的核心能力集中在**协作层**：多用户、权限/LDAP/SAML、实时协同编辑、评论、工作流。另有几条与我们相关：

| 平台能力 | 对 CQM 的价值 | 判断 |
|:---|:---|:---|
| 强搜索（分面/同义词/高亮） | 高 | **已部分自研**（结构化层 342 条 + Material 全文层） |
| 版本历史/页面历史 | 高 | **git 已提供**，无需另建 |
| 导出 PDF/EPUB | 中 | 待补（讲稿分册天然适合出册） |
| 内建图表（Mermaid/Excalidraw） | 中 | 图谱已有 Cytoscape；Mermaid 已在阅读站随包 |
| API | 中 | 仅在上了本地服务后才有意义 |
| 协作编辑/权限/SSO | 低 | **单作者 git 项目不需要**，引入即纯负担 |

**结论**：这一类平台**整体不采用**——它们是给团队用的，我们是给一个研究者 + 一批外部读者用的。

### 1.3 "应用级"要付的代价（三元组库与检索）

- **三元组库**（来源 [6][7]）：我们只有 **5,567 个三元组**，属于"一个集合的小规模"。选型上：
  - **Oxigraph**（Rust，单二进制，`oxigraph serve` 即得 `localhost:7878` + **自带 YASGUI 界面**，无 JVM，支持 Turtle/N-Triples/RDF-XML/JSON-LD 与 SPARQL 1.1）——**最契合**：一个可执行文件、一条命令、浏览器直接写 SPARQL；
  - **Apache Jena Fuseki**（`fuseki-server --file=x.ttl /ds`，一条命令起端点 + 浏览器 UI）——备选，需 JVM；
  - GraphDB/Virtuoso——规模与授权都不匹配，不采用。
  - 三者迁移成本低（标准 RDF/SPARQL，导出即换），所以这个选择**可逆**。
- **检索**：若上本地服务，可叠 Meilisearch/Typesense（分面/容错/同义词）；但当前规模（342 条结构化 + 44 页全文）自研已够，**先不引入**。
- **Spring Boot 的具体位置**：它是 Java Web 框架，长处是单 jar 部署、生态全（Jena 可在同进程做推理）。本项目**已经装了 Java**（HermiT 推理要用），所以 Spring Boot 不是不能上。但对我们的需求（实时 SPARQL + 检索 + 复核写回），**Python/FastAPI 复用现有工具链**（rdflib/pyshacl/jieba 都已装）摩擦更小；Spring Boot 只在"想把 OWL 推理也放进同一个服务进程"时才划算。见 §4 的取舍表。

## 3. 目标信息架构：一个站，四个象限

把 Divio 四象限落到导航上（括号内为现有或待建内容）：

```
CQM 研究站（阅读站）
├── 首页                          # 项目一页总览 + 状态读数（Lean 覆盖 41/82、缺口 24、证据 215）
├── 教程（Tutorial）              # 从浅到深：展开链讲稿分册（L001–…）+ 专题导读（讲解文档/）
├── 解释（Explanation）           # 理论原文 01–07（链条层）+ 量纲与群论专章
├── 参考（Reference）             # 概念条目页 / 命题 / 缺口台账 / 符号索引 / 证据映射 / SPARQL 问答
├── 操作（How-to）                # 证据复核工作台 · 复现与重建指南 · 缺口怎么读 · 如何新增一条断言
└── 可视化                        # 可推演超图 · 研究驾驶舱 · 检索台 · 形式化蓝图
```

四条设计规则：

1. **四象限 = 四种深度，不是四个站**。讲稿的深度滑杆（导读/概念/链条/技术）与 Divio 四象限正交：前者管**同一内容的不同粒度**，后者管**不同用途**。两者叠加才既读得进又查得到。
2. **参考象限的每个条目都要能跳到权威处**（概念→原文定义处、缺口→台账与 Lean、证据→字符区间）。这一条我们已经做到，清理时不能丢。
3. **操作象限是本方案最重要的新增**——它直接服务"待第三方复现"：复现指南把 `_build` 顺序、依赖、校验和、RO-Crate 写成交代式步骤；复核工作台把 215 条引文的人工确认变成可执行的活。
4. **断点在四个象限都可见**（深度滑杆已保证讲稿层；参考象限的缺口条目本就带状态）。

## 4. 三档技术路线

| | **A · 静态单站精修**（推荐起点） | **B · 本地服务应用** | **C · 混合渐进**（推荐终局） |
|:---|:---|:---|:---|
| 形态 | 纯静态站点（现状延长） | Spring Boot / FastAPI 常驻服务 + 前端 | 静态站为默认，**本地服务可选增强** |
| 打开方式 | `file://` 双击 | `http://localhost:PORT` | 静态双击即用；起服务后自动多出能力 |
| 能多做什么 | 内容与导航重组、条目页、局部图、导出 | **实时 SPARQL**、实时检索、**复核写回**、API、可编程复算 | A 的全部 + B 的全部（按需开启） |
| 代价 | 低（只动构建脚本与内容） | 中高：常驻进程、启动步骤、写回路径与冲突、需维护 | 中：多一层"服务探测 + 降级"逻辑 |
| 对离线红线 | 完全满足 | **破坏**（`file://` 不可用时实时能力全无） | **满足**（服务缺席即降级为 A） |
| 对三条红线 | 满足 | 满足（写回仍走三关制） | 满足 |
| 适合谁 | 现在 | 需要"别人也能跑起来复现"时 | 终局 |

**为什么推荐 C 而不是直接 B**：本项目的读者大概率是"拿到仓库 → 双击 index.html"的人。B 会让这一击失效。C 的做法是：站点启动时探测 `http://127.0.0.1:PORT/health`，通不了就不显示任何服务相关入口（现在检索台的"SPARQL 能力问答"已经是**构建期内嵌结果**的形式，正好作为降级态）；通了才亮出"实时 SPARQL / 写回复核"。

**若确要上 B，技术选型**：

| 需求 | 首选 | 理由 |
|:---|:---|:---|
| 实时 SPARQL | **Oxigraph**（单二进制 + YASGUI） | 5,567 三元组属极小规模；无 JVM；一条命令起服务；可换（标准 RDF） |
| 备选 | Apache Jena Fuseki | 需 JVM，但一条命令同样起端点 |
| 服务框架 | **FastAPI（Python）** | 复用现有工具链（rdflib/pyshacl/jieba/mkdocs 均已在 Python 侧） |
| 服务框架（备选） | Spring Boot | 仅在"要把 OWL 推理（Jena/HermiT）并入同一进程"时才划算；本项目已装 Java |
| 检索 | 暂不引入（Meilisearch/Typesense 备用） | 当前规模自研已够 |

### 5.1 批 5 的实际落地（2026-10-13，用户裁定"直接 Spring Boot 一步到位"）

用户选择跳过 A/B 渐进，直接上服务端。实际交付 **`09_研究站服务/`（Spring Boot 3.3.5 + Jena ARQ 4.10，编译目标 Java 21）**，与上述 C 路线等价但一次到位：

| 项 | 实际 |
|:---|:---|
| 入口 | `http://127.0.0.1:8080/` 即阅读站（静态站点挂载为 Web 根），`/api/**` 为 API |
| 实时 SPARQL | Jena **内存模型**载入 `知识图谱.ttl`（5,146 三元组）；默认只读（写操作 403），可配置放开 |
| 结构化检索 | 321 条文档（概念 82 / 命题 63 / 论证 70 / 缺口 24 / 符号 21 / 链条步 131 去重后），CJK 一元+二元 + 拉丁词打分，可按 `type` 过滤 |
| 条目接口 | `/api/concepts[/{id}]`、`/api/props`、`/api/gaps`、`/api/evidence/{id}`、`/api/chain` |
| **证据复核写回** | `POST /api/review` → `00_外部引用/复核结果.csv`（列 `struct_id,verdict,reviewer,note,reviewed_at`，与 `check_provenance.py`/`build_evidence.py` 期望一致；同 struct_id 覆盖式重写 + 原子落盘；`approved` 强制复核人；未知 id 拒 400） |
| 降级 | 站点 `assets/cqm-enhance.js` 的 `probeService()` 软探测 `api/status`：服务在场才亮"服务已连接"徽标，`file://` 或服务缺席时静默无徽标 |
| 构建 | 项目内 `settings.xml` 把中央仓库镜像到阿里云（本机直连 central 不通）；`启动.bat` 一键起 |

**踩坑记录（三条，均已解决）**：①自定义静态资源位置不会把 `/` 映射到 `index.html`，需 `HomeController` 显式 `forward:`；②资源路径含 `..` 时 `toUri()` 不归一化导致 404，需 `toAbsolutePath().normalize()`；③Windows 下**运行中的服务会锁住 jar**，`mvn package` 的 repackage 阶段失败——改构建前须先停服务。

**验收**：端到端脚本 `.workbuddy/tools/verify_station.py` **27/27 通过**（静态站点 4 / status 9 / 检索 2 / SPARQL 3 / 条目 4 / 复核写回 5；写回测试产生的 `复核结果.csv` 已清理，仓库无残留）。

**与方案的偏差（如实登记）**：方案建议 FastAPI，实际按用户要求用 Spring Boot；三元组库用 Jena 内存模型而非 Oxigraph（同进程、无需第二个服务，5 千级规模下等价）；`target/`（37 MB jar）与运行日志已加入 `.gitignore`，不入库。

## 6. 明确不做

1. **不引入协作层**：多用户、权限、SSO、实时协同编辑——单作者 git 项目不需要（§1.2）。
2. **不把站点搬到需要常驻进程的形态作为默认**：`file://` 双击即用是不可让渡的（§4）。
3. **不引 CDN / 云端托管 / 外部检索服务**：离线红线。
4. **不用生成模型写内容**（§2.6 既定结论）：讲稿由作者撰写，抽取层只做定位与归一。
5. **不为"看起来高级"换技术栈**：站点继续用 Material for MkDocs + 自包含 HTML；三元组库只在需要实时查询时才上。
6. **不删 `11_元数据/` 与 `讲解文档/`**（R7/R8 判定为保留）。
