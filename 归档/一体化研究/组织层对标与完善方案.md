## 0. 结论速览

一句话：`08` 的**数据层与校验层已达同类项目里少见的完整度**（215 条断言 100% 逐字可回溯、SHACL 零违约、HermiT 一致、41 项跨产物硬检查），**短板集中在"人看的那一面"**——阅读站是纯文本、图谱单独挂在另外两个页面、证据复核没有界面、公式与常数没有机械检查，而读者拿不到一条能读的展开链。因此完善的重点不是推翻重来，而是**把已经算出来的东西接到读者眼前**，并补齐四处"只有机器定位、没有机器检查"的环节。

## 2. 对标：六个坐标系

### 2.1 形式化蓝图系（leanblueprint / FLT / physlib）

- **主流做法**：形式化项目普遍用 `leanblueprint`（plasTeX 插件）把 LaTeX 陈述与 Lean 声明双向绑定：正文里的定义/定理与代码互链，自动生成**依赖图**（节点形状区分定理/定义/引理，颜色区分"可陈述/可证明/未就绪/已并入 mathlib"），同时产出 Web 视图与 PDF，CI 在每次推送后重建。`doc-gen4` 负责 API 文档。来源见附录 [1][2]。
- **`08` 现状**：`10_展示可视化/蓝图/index.html` 与 `04_Lean对接/蓝图/` 为自研生成物；`leanblueprint`、plasTeX 未安装。
- **差距**：节点状态着色、`\uses` 依赖边、`\lean{}` 双向链接这三件事目前由自研脚本近似实现，**没有按"逐条陈述 ↔ 声明"配对校验**。
- **直接可借**：①把现有蓝图升级为真 `leanblueprint`（保留自研 HTML 作为降级产物）；②借用它的**状态色语义**（未就绪/可陈述/可证明/已证）作为缺口台账在可视化中的统一色带。

### 2.2 物理形式化系（physlib，原 PhysLean）

- **主流做法**（来源 [3]）：社区项目 physlib 的几条硬性要求值得逐条对照——每个定义与每个模块都必须带物理说明；项目内置 **`sorryful` 属性与对应 linter**（把 `sorry` 变成显式可审计对象）；有 `runPhysleanLinters` 统一入口；网站上有 **DocumentationTracker** 追踪文档覆盖进度，并有项目 **treemap** 图；还公开"适合上手的切入点"清单（Maxwell 方程、量子谐振子、Wick 定理 …）。
- **`08` 现状**：Lean 侧有 `lake build` + `--wfail`，但 `sorry`/`axiom` 依赖**靠人工检索清单**（见全栈方案 §4.3），没有 linter 级机器台账；文档侧无覆盖率追踪图、无 treemap、无"上手切入点"清单。
- **差距**：`08` 最强的正是"诚实边界"（41/82 覆盖、19 条词表不对齐如实登记），但**没有把它们画出来**，读者要读表才能感知。
- **直接可借**：`sorryful` 式 linter → 见 P4；DocumentationTracker / treemap → 见 V3；上手清单 → 见 R3 与 §6 B2。

### 2.3 语义知识组织系（ORKG / Wikidata / QUDT·OM）

- **主流做法**：
  - **ORKG**（来源 [4]）：把论文贡献拆成机器可读的断言，用**模板**约束描述结构，自动生成**对比表**（同一研究问题下多个贡献并排），对比表本身可被引用（带 DOI）。它的核心洞见是：*模板即数据契约，对比表即人机共用的阅读界面*。
  - **本体与单位**（来源 [5][6]）：量纲类知识普遍落到 QUDT 或 OM 上——QUDT 用**量纲向量**（$L^aM^bT^cI^d\theta^eN^fJ^gD^h$）刻画量纲，配 `conversion multiplier/offset` 支持换单位；OM 2.0 把"量纲种类"建模为 OWL 类并把复合单位分解为构成单位，其用例之一就是**校验公式**。两者都被用于"自动量纲一致性检查"。
- **`08` 现状**：SHACL 已经是数据契约，`论证对齐.csv`/`缺口编号对照.csv` 已经是"对比表"雏形；但**量纲没有被建模成可计算对象**——`01 核心理论/CQM_核心_量纲与群论.md` 里的 $K_L,K_M,K_Q,K_\Theta,K_N,K_J$ 与 $T,L,M,Q,\Theta,N,J$ 只存在于文字与表格中。
- **差距**：CQM 自己的量纲理论是全项目最"可机械验证"的一部分，却恰恰没有任何机械检查；公式没有编号清单，也没有齐次性检查。
- **直接可借**：量纲向量 + 齐次性检查 → 见 P1；常数值台账 → 见 P2；对比表式界面 → 见 V2/V3。

### 2.4 打包与可复现系（RO-Crate / FAIR）

- **主流做法**（来源 [7]）：RO-Crate 1.2（2025-06-04 成为 Recommendation）规定：在任何目录里放一个 `ro-crate-metadata.json`（JSON-LD），该目录即成为一个可分发、可归档、可引用的研究对象；支持 **profile crate**（专门化子档）与 **detached crate**；元数据里可嵌 **SPDX 校验和**、许可证、如何引用、如何复用；并通过 FAIR Signposting 支持机器抓取。
- **`08` 现状**：`11_元数据/manifest.json` 已逐文件记录 `bytes/mtime/sha256`（228 条），`知识图谱.ttl` 已有 PROV-O 证据链——**这正好是 RO-Crate 需要的原料**。
- **差距**：这些元数据只对本项目脚本可读，外部工具读不懂；"待第三方复现"因此停在声明层面。
- **直接可借**：把 `manifest.json` + PROV + SHACL 契约映射成 RO-Crate，一步换来"可被外部工具抓取、可归档、可引用"→ 见 P8。

### 2.5 阅读与呈现系（Material / 语义检索 / 浏览器端 SPARQL）

- **主流做法**：
  - 离线文档站已形成成熟惯例：Material for MkDocs 用 lunr/jieba 做客户端检索、`offline` 插件保证 `file://` 可用、`privacy` 插件把外部资源本地化——`08` 已经用了这套，属于**跟上了主流**。
  - 检索侧的主流是**混合检索**：稠密向量（如 bge-small-zh 这类 24M 参数、约 96 MB、可 CPU 推理的中文小模型）与稀疏（BM25）并行，用 RRF 融合，再加一层交叉编码器重排；有中文选型文档给出的经验是"加一层重排通常比换更大的嵌入模型更划算"。来源 [8]。
  - 图谱侧的主流是**浏览器内 SPARQL**：Comunica（TypeScript、MIT、可在浏览器运行）与 Oxigraph（Rust 编译为 WASM 的 SPARQL 引擎）都已能在浏览器内跑查询；公开对比中 Oxigraph 比 "Comunica + N3.js" 快约 20 倍，但受 WASM 32 位地址限制，线性内存上限 4 GB。来源 [9]。
- **`08` 现状**：检索台是自研 BM25 + 构建期内嵌的 SPARQL 结果；**没有浏览器端可交互的 SPARQL**，因此"别人想自己问一句"无法自助。
- **直接可借**：混合检索（R5，去重排版）；浏览器端 SPARQL（P7）；语义地图（V4）。

### 2.6 生成模型系（PaperQA2 / 引文核验）——对标结论：不采用

- **主流做法**（来源 [10][11]）：面向科学文献的 RAG 系统（PaperQA2 一类）采用 agentic 检索 + **重排与语境化摘要（RCS）**：先向量召回，再用 LLM 对每个片段生成"针对该问题的语境化摘要"，用摘要而非原文块进入最终作答，并强制**行内引文指回具体来源**。它在 RAG-QA Arena 的科学子榜上取得 SOTA（比最接近的竞争系统高 12.4%）。另一侧的证据同样重要：多文档综述基准 ScholarQABench 把**引文精确率/召回率**作为一等指标，并指出基线模型可能凭空生成 78–90% 的引用。
- **本机生成模型评估结论（2026-10-12）**：`D:\WorkSpace\AI\llm` 上可用的是 Qwen3-1.7B 量化版与 0.6B 级 CQM 微调模型；其自述为"CQM 文档风格的生成/检索器，不是数学推理引擎"（0.6B 版明确写有"数学逻辑不严谨：术语、公式、章节结构都对，但推导不保证成立"）。据此判定：**本地生成模型不作为任何环节的生成源**；`_build/llm_extract.py` 保持就绪状态但**不接线**（不删除、不纳入路线）。
- **仍然采用的部分**：PaperQA2 的两条**校验思想与模型能力无关**——① 任何结论都必须带指向具体来源的行内引文；② 检索后先做语境化归并、再作答。前者转化为本方案的逐字 span 校验（P5/R4），后者转化为**抽取式**速览（R1）。
- **替代路径**：凡原先指望模型做的环节，一律改为"规则/统计提案 + 机械校验 + 人工确认"三关（详见 §4 P6）。

## 3. 可视化：把算出来的东西接给读者（V1–V8）

**V1 · 阅读站 ↔ 图谱双向直达**
- 做法：沿用阅读站已有的自研注入机制（`assets/backlink-inject.js`），在每页正文之后注入三块"本页索引"：本页涉及的概念（→ 概念本体页）、本页涉及的缺口（→ 缺口台账锚点）、本页的断言证据（→ 证据面板）。反向：在检索台/驾驶舱的节点上增加"在阅读站中打开该文档"的深链（`use_directory_urls: false` 意味着平铺文件名可直连）。
- 验收：任取 5 篇文档，页面底部出现三类卡片；点任一卡片能落到对应条目且不出现死链（`check_consistency` 的 Markdown 链接检查覆盖该批新链接）。

**V2 · 缺口总图（分层 DAG + 状态色带）**
- 做法：以 `缺口编号对照.csv`（24 缺口）+ `缺口依赖.csv` + `命题依赖.csv`（291 边）为源，渲染分层有向图：节点＝缺口/命题，颜色＝闭合状态，形状＝缺口类别，边样式＝依赖类型（人工/同证据句/语义近邻），并**显式区分"人工确认"与"机器推断"两类边**（现在 `method` 列已有这个信息，图上没有体现）。采用 2.1 借来的状态色语义，使蓝图、缺口图、覆盖度图三处配色一致。
- 边界：`命题依赖.csv` 的边多为"依据文档/提及概念/证据文档/证据句提及概念/语义近邻"等**证据型**关系，**不是逻辑依赖**；图上必须按关系类型分色，且不得把证据型边读作推理边。
- 验收：图上"人工确认"边与 CSV 中 `verified` 为真的记录逐条一致；缺口状态与台账无一处不符。

**V3 · 覆盖度总图（treemap + 覆盖矩阵）**
- 做法：82 概念 × 5 条腿（源表 / 证据 / RDF / Lean / 别名）的覆盖矩阵热图；另以 treemap 呈现"目录 → 文档 → 已结构化条数/总段数"，把 21 篇零覆盖语料直接染色标出。
- 验收：矩阵每格可由 `00/01/02/03/04` 的既有 CSV 复算得到；零覆盖文档集合与 `01_结构化数据/README.md` 的登记一致。

**V4 · 语义地图（二维投影）**
- 做法：现有 `05/嵌入就绪/语义近邻.csv` 是 TF-IDF 近邻，没有平面投影。用 CPU 侧的中文小嵌入模型（无 GPU 占用）编码概念名＋定义，UMAP/t-SNE 降到二维，做交互散点：颜色＝维度、大小＝证据条数、悬停显示近邻，点击进概念页。
- 验收：投影坐标与近邻表一起入库（可复算）；图上任意两点距离不作为理论陈述（标注为**呈现用投影**，避免"可视化即断言"）。

**V5 · 证据复核工作台（人机界面）**
- 做法：`证据映射.csv` 的 `verified` 现全为 `False`，`check_provenance` 已预留"存在 `00_外部引用/复核结果.csv` 时升为 13 项"。做一个逐条核对界面：左侧原文（用 `char_start/char_end` 定位并高亮 `quote`），右侧断言（`struct_id/name/kind`），底部三键（通过 / 驳回 / 存疑）+ 备注，导出即 `复核结果.csv`。生成物为**自包含单页**，与现有驾驶舱同规格（零外部依赖、离线可用）。

**V7 · 图形可下载 + 无障碍**

## 6. 展开链讲稿：要不要写、怎么写（B1–B4）

**要不要写：要，但不能写成"教科书式的平滑叙述"。**

- **理由**：`01–07` 是**研究文档**——按主题分册、层层自指、术语先于定义出现、大量限定语与缺口标注。对作者是完备的，对读者是**非线性**的：要读出"物质先在 → 质数自组织 → GL(5) 潜能先在 → SU(5) 基态 ⇒ 重组实现 ⇒ U(1)×SU(2)×SU(3)"这条链，读者得自己跨 5 个目录拼。同类项目的做法印证了这一点：physlib 明确列出"上手切入点"，并维护 DocumentationTracker（来源 [3]）。
- **价值**：展开链是**可检验性的前置条件**。P8 的 RO-Crate/DOI 解决"能不能复现"，展开链解决"能不能读到复现所需的那一步"。
- **风险（关键）**：书式叙述天生倾向"抹平缺口"——写成流畅因果链，会不知不觉把"构造假设"读成"已证定理"，把并列登记的两种取值读成一条值链。这直接撞三条红线，尤其撞"不绕过"。因此：

**B1 · 撰写式展开链（2026-10-12 修订：本地生成模型弃用后，改由作者侧撰写）**
- **判定修订**：原先设计的"逐字拼装"路线**不足以承担"拉通展开"**——它产出的是材料的次序，不是论述。展开链必须是**撰写**：有作者的声音、有从浅到深的推进、有对"为什么这一步必须在这里"的交代。
- **撰写不等于自由发挥**：每个展开步仍然是一个结构化条目（`step_id / 提问（这一步回答什么）/ 正文（撰写文字）/ 锚点（文档＋章节，必要时到字符区间）/ 前提步 / 状态标签 / 限定语在场标记`），与拼装式的区别只在正文由撰写产生。
- **四条可检查的纪律**：①**锚点齐备**——凡陈述理论内容的句子都挂锚点；②**六关自检**——出处存在／对象正确／段落相关／论断被支撑／**限定语保留**／来源适配（第六关见 §9.5）；③**未核对就标注**——尚未回到原文逐字核对的锚点，在锚点表里标「待逐字核对」，不得含糊；④**断点就地**——缺口写在正文该出现的位置，不集中到附录、不用"因此"跨过。
- **明确不做的**：不使用生成模型撰写理论内容（§2.6）；不把索引行的摘要当权威；不为原文补理由（原文未展开动机处，直接写"原文未在此处展开"）；不跨文档统一并列口径（$K_L$ 的多条值链、28/30 公理双口径原样并列）。
- **落地格式**：`一体化研究/展开链讲稿/` 分册制，每分册对应链条的一段；正文进阅读站（`L001` 起，导航紧随展开链页）。

**B2 · 同一批 step，四种深度（不是四本书）**
- 导览层：只讲动机与问题，不出现公式；概念层：给定义、符号与图，不进入推导；链条层：完整 step 序列＋状态标签＋缺口断点（这是"拉通"的主干）；技术层：直接指向 `01–07` 原文段落与 Lean 声明（由 `04_Lean对接` 的映射给出），不再复述。
- 阅读器上是**一个深度滑杆**：同一页面切四层，四层共用同一 step 数据源——这样**不可能出现口径分叉**（四份独立文件迟早漂移）。
- 顺带解决两件事：导览层＝R1 的速览，链条层＝R3 的主干动线。

**B3 · 断点必须画出来**
- 链条上每个缺口都是**断点**，且必须在图上可见（与 V2 缺口总图共用数据源）：`已证 → 构造假设 → 缺口（附编号） → 缺口之后仍可继续的下游`。
- 断点清单直接由 `缺口编号对照.csv`（24 缺口 + 8 条前缀冲突）与 `缺口依赖.csv` 生成，**不新增编号**；跨缺口的句式强制为"在缺口 X 未闭合的前提下，下游成立的是…"。

**B4 · 书稿进度与理论进度共用一个仪表**
- 页面顶部显示"本页 step 数 / 已陈述 / 待证明 / 未闭合 / axiom"（直接取自 step 的状态分布）。这样"书写到哪"与"理论证到哪"是同一个读数，**不会出现讲稿看起来比理论更完整**的情形。

## 8. 边界与反模式
1. **可视化只呈现，不定义**：任何图、徽章、速览、讲稿都不得成为理论表述的权威来源；权威源仍是 `README.md` 与概念权威定义处。
2. **讲稿不得平滑缺口**：跨缺口必须显式声明前提未闭合；状态标签与限定语在所有呈现面上必须可见。
3. **不引入在线依赖**：阅读站、驾驶舱、检索台、复核工作台一律自包含、`file://` 可用、零 CDN——这是既有离线红线。
4. **不用生成模型撰写理论内容**：本地生成模型不作为论断、公式、数值、正文的生成源；一切"命题"级产出必须经人工确认（候选池红线）。
5. **候选池不越界**：抽取器与工具的产出**只能进候选池**，写入源表必须经人工确认（三关制）。
6. **不自动改数**：常数值/公式检查只报告，不改写；数值变更只能由人做出，且须注明依据。
7. **不为"看起来更精确"换更大模型**：精确性来自机械校验链（逐字引文、SHACL、HermiT、CI 门禁），不来自生成式模型。
8. **不牺牲可回溯换排版**：任何渲染优化若导致公式宏支持下降或引文不可点，即回退。
9. **缺口与限定语原样**：缺口语义、编号、状态不得因可视化而"看起来已闭合"。

## 9. 高级检索与高级可视化：选型与本次落地

### 9.1 检索选型（为什么不是 Pagefind / Algolia / MiniSearch）

| 方案 | 优点 | 本机约束下的结论 |
|:---|:---|:---|
| **Pagefind**（来源 [12]） | 构建期索引、按需分块（万页 < 300 kB）、中文分段好、Starlight 默认、零服务 | 索引经 `fetch`/Worker 装载，**`file://` 下不可用** → 不采用（与 v1.8.0 的判断一致） |
| Algolia DocSearch / Meilisearch / Typesense | facet、容错、同义词、结果分析齐全，是文档站主流 | 需要托管服务或本地常驻服务 + 联网，违反离线红线 → 不采用 |
| **lunr（Material 内置，已在用）** | 倒排索引、官方 zh 支持、构建期 jieba 预分词 + 用户词典 | 无 facet、无结构化字段、无模糊 → **保留作全文层** |
| MiniSearch / FlexSearch / Fuse.js（来源 [14]） | 客户端倒排 / 模糊，`storeFields` 可直接出摘要，可 inline | 需引入并随包维护第三方 JS；本机离线可打包但增维护面 → 本次不引入 |
| **自研结构化检索（本次采用）** | 零依赖、可整段 inline、字段与 facet 完全按本库结构定制 | 双层检索的**结构化层**：概念 82 / 命题 39 / 缺口 24 / 符号 21 / 文档 42 / 展开链 131 步 |

**最终形态＝双层检索**：全文层用 Material 内置（lunr + jieba + CQM 用户词典，4.3 MB 索引已 inline，`file://` 可用）；结构化层用自研覆盖层（`Ctrl/⌘+K` 或 `/` 唤出，分类 facet、CJK 一元＋二元打分、`<mark>` 高亮、`↑↓`/`Enter` 键盘导航，并可携词一键转全文检索）。两层各司其职：全文找"哪里提到过"，结构化找"这条概念／缺口／符号是什么"。

### 9.5 撰写方法论的对标（本稿怎么"写得浅、写得准"）

- **分层不等于简化**（来源 [15]）：Bret Victor 的"抽象之梯"给出一个可直接照搬的判断——**价值不在任何单一层级，而在层级之间的往返**：往上走"抽象掉一个参数"从而看见模式，往下走"选定一个取值"从而看清原因；静态媒介（公式、固定图）的问题是把你锁死在少数层级上。这正是本方案把读物做成"同一批 step 的四种深度 + 一个深度滑杆"而不是"四份文件"的理由（B2）。
- **写的准要有关卡**（来源 [16]）：引文保真研究把"引用正确"与"引用保真"分开，并给出六步验证链——出处存在 → 对象正确 → 段落相关 → 论断被支撑 → **限定语保留** → 来源适配；同时报告了一个值得警惕的量级：基线系统里凭空生成引用的比例可达 78–90%，而"引用看似正确"也不等于论断真有来源支撑（另一项 2025 年研究报出高达 57% 的引用缺乏因果保真）。本稿把它落成**附录 B 的六关自检**，并把第 5 关（限定语保留）当作最高风险关：去掉限定语，句子会立刻变漂亮——这正是"写得好读"与"写得准"分道扬镳的地方。
- **本稿的自我约束**：锚点表公开"核对状态"（逐字核对／待逐字核对），而不是笼统标"已核对"；未核对的锚点照实标出，读的时候就知道该以什么状态对待那一条。
