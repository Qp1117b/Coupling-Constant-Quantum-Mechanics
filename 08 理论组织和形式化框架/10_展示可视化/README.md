**呈现边界**：全部图表、证据、检索与回放数据均取自既有产物（源 CSV、`超图数据.json`、`知识图谱.json`、`证据映射.json`、`06_动态机制/仿真/derivation_order.csv`、`Lean结构提取/declarations.json` 等），构建期断言与源一致；不新增理论内容、不改数值、不改缺口状态。

**单一入口（2026-10-13 更新）**：可视化已收敛为**一个站点**——`阅读站VitePress/`（**VitePress v1.6.4**）为唯一入口。原 Material 站 `阅读站/` 已于 2026-10-13 **删除**，不再保留（`file://` 离线副本需求时可用 `_build/build_reader_site.py` 重建，但生成器是 Material，非默认路径）。左侧「可视化」栏目内嵌四件自包含 HTML（可推演超图／研究驾驶舱／检索台／形式化蓝图），源文件收敛在 `源_可视化/`（研究驾驶舱／检索台／超图交互，蓝图在 `04_Lean对接/蓝图/`），由 `_build/build_vitepress_site.py` 构建期复制到 `阅读站VitePress/docs/public/viz/`（站内以 `/viz/` 引用，含随包的 `cytoscape.min.js` 与 `驾驶舱数据.json`），**不改源文件**；`03_超图与理论图/` 下不再保留超图副本。

**应用层（2026-10-13）**：`09 研究站服务/`（Spring Boot）把 `阅读站VitePress/.vitepress/dist` 挂为自己的 Web 根，并在同端口提供 `/api/**`：实时 SPARQL（Jena 内存模型）、结构化检索、概念/缺口/证据/链条条目查询，以及**证据复核写回**（`POST /api/review` → `00_外部引用/复核结果.csv`，与 `check_provenance.py` 的期望一致）。**VitePress 站须经 HTTP 提供**：服务在场时直接访问 `http://127.0.0.1:8080/`；服务缺席时需其它静态服务器托管 dist（`file://` 直开因绝对路径 `base:'/'` 会丢资源）。站点通过软探测 `api/status` 在服务在场时显示「服务已连接」徽标。启动：`09 研究站服务/启动.bat`（本机用 `mvn package` + `java -jar`，见该目录 README）。

**阅读站增强（v1.9.0，2026-10-12）**：术语卡与缺口卡的文字**逐字**取自 `01_结构化数据/概念表.csv`、`缺口编号对照.csv`、`09_桥接与翻译/符号对照表.csv` 与 `00_外部引用/证据映射.csv`，构建脚本只做拼装、不改写；展开链页的每条都是原文逐字片段，顺序由「文档层级 → 文档 → 行号」机械决定，箭头语义不统一解释；缺口状态与限定语原样呈现。站点为**呈现层**，权威源仍是各文档原文与 `README.md`。卡片内公式由构建期转换为 MathJax 分隔符并在插入后重排（`MathJax.typesetPromise`）。

**打开方式**：① 推荐——先起研究站服务（`09 研究站服务/启动.bat`），浏览器访问 `http://127.0.0.1:8080/` 即 VitePress 站（含内嵌可视化与全部增强）；② 直接用浏览器打开源文件 `源_可视化/研究驾驶舱/index.html`（9 面板驾驶舱）、`源_可视化/检索台/index.html`（图谱/全文/证据检索 + 证据复核）、`源_可视化/超图交互.html`（可推演超图）——均为自包含 HTML，蓝图在 `04_Lean对接/蓝图/index.html`；③ VitePress 产物 `阅读站VitePress/.vitepress/dist/index.html` 须由静态服务器托管（`file://` 直开丢资源）。构建：`_build/build_site.py`、`_build/build_search.py`、`_build/build_vitepress_site.py`（`_build/build_reader_site.py` 现仅用于生成 staged 中间物 `_build/mkdocs_src/`，其 Material 产物已不再保留）。
