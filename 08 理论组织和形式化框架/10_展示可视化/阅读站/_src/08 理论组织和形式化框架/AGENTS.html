    08 理论组织和形式化框架 · AI 协作规范（七维度运行手册）¶

    本文件是 08 理论组织和形式化框架/ 的目录级规范，补充根 AGENTS.md。 目的：使任何一次 AI 研究或修改都按七维度闭环执行，不遗漏、不旁路、不把组织层当装饰。 凡在本目录内工作（读取、分析、增改、生成），先读本文件。

    一、适用与优先级¶

    冲突项 裁决顺序
    规范优先级 根 AGENTS.md > 本文件 > README.md > 设计方案.md
    数据权威 README.md 符号约定与数值表 > 一体化研究/附录/术语表.md > 一体化研究/附录/缺口台账.md > 各文档概念权威定义处
    结构权威 01_结构化数据/*.csv 为唯一源；其余产物（JSON/OWL/HTML/PNG/映射）皆为其派生

    二、三条不可违反的边界（承袭根 AGENTS 三条红线）¶

    1. 外部文本不动：01–07 理论文档不修改；本目录只存引用、锚点、结构化数据与形式化产物。
    2. 缺口原样：缺口语义、编号（C / G2–G8 / G9–G22 / N1–N4 / H3.1–H3.3 / A–E；G6 未定义）与状态不得升级为"已证""已闭合"。
    3. 不引入理论外：不得新增 CQM 未涉及的观点、术语、数值、文献、编号。

    三、七维度责任矩阵¶

    # 维度 角色 目录 触发条件（何时必须处理） 必须同步的产物
    1 结构化 核心 00–03 概念/命题/论证有任何增改 概念表/命题表/论证表 → 超图数据.json → .dot/.svg/.png → 超图可视化.html
    2 ML 数据准备 核心 05 概念/论证/关系增改 node_features、hyperedge_index、edge_index、heterodata、证明数据集
    3 形式化验证 核心 04 08 理论组织和形式化框架/04_Lean对接/Lean源码/ 有新增或改动 Lean结构提取/、Lean↔概念映射.csv、蓝图/
    4 动态机制 辅助 06 论证表增改 重写规则.json、初始状态.json、仿真轨迹与 dynamic_hypergraph
    5 经验检验 辅助 07 命题/缺口/数值增改 因果模型、贝叶斯网络、实验设计
    6 元理论反思 辅助 08 方法论/术语口径变化 范畴论模型、类型论基础、哲学假设
    7 展示可视化 核心 10 任一上游数据结构变化 网站/、交互式可视化/、蓝图/、讲解文档/、阅读站/（由 01–07 文本派生）
    — 概念本体 支撑 02 概念/关系类型增改 本体.owl、概念关系图.png、本体统计.json
    — 桥接与翻译 支撑 09 符号/术语/映射变化 符号对照表、文档间等价映射、概念Lean物理映射
    — 元数据 支撑 11 任一产物变化 manifest、版本、变更日志、验证状态

    七维度 = 4 核心 + 3 辅助：核心维度为 1 结构化、2 ML 数据准备、3 形式化验证、7 展示可视化；辅助维度为 4 动态机制、5 经验检验、6 元理论反思。概念本体 / 桥接与翻译 / 元数据为支撑层，不计入七维度。

    原则：源 CSV 是"因"，其余是"果"。研究产出的新事实先落到源 CSV，再重跑脚本派生，不得手工改派生文件。

    四、研究闭环（Definition of Done）¶

    凡发生下表左侧变更，必须完成右侧全部同步，并运行一致性检查：

    变更类型 必做同步（按序）
    新增/改概念 概念表 → build_base → build_evidence → build_claims → build_ontology → build_kg → build_ml → build_extract → build_bridge → build_site → build_search → build_meta
    新增/改命题或缺口 命题表 → build_claims → build_evidence → build_ontology → build_kg → build_ml（命题-证明对）→ build_causal（贝叶斯网络）→ build_site → build_search → build_meta
    新增/改论证或关系 论证表 → build_base → build_claims → build_evidence → build_ontology → build_kg → build_ml → build_dynamics → build_bridge → build_site → build_search → build_meta
    新增/改 Lean 声明 build_lean → build_kg（Lean 映射入图）→ build_ml（lean声明.jsonl）→ build_site → build_meta
    术语/符号/口径变化 build_bridge → 02/术语符号一致清单.md（登记）→ build_claims（别名词表）→ build_kg → build_meta
    任意产物变化 build_meta 重生成 manifest，并更新 11_元数据/变更日志.md

    收尾必跑：

    python "08 理论组织和形式化框架/_build/check_provenance.py"   # 证据层：引文必须逐字等于原文区间
python "08 理论组织和形式化框架/_build/check_consistency.py"  # 组织层：41 项跨产物硬检查

    未通过即视为研究未完成——不得以"仅更新了文档"结项。

    五、一致性红线¶

    1. 箭头：⇒ 仅表重组实现（Hyperedge，多元）；演化/映射/极限/依赖/层级含于一律 →；等价用 ↔。⇒ 与 → 不得合并为同一张简单图。
    2. 缺口编号三套不混用：C/G2–G8、G9–G22、N1–N4（另 H3.1–H3.3 axiom、集成理论 A–E 局部编号）。
    3. \(G_N\) 限定语：凡 \(G_N\)、\(\alpha\) 类数值或偏差，必须带"构造后验数字校验，待独立复现"。
    4. 术语表"不得擅自统一"项：\(\Delta\delta_v\) 与 \(\Delta\delta_0\)、\(K_{\text{eff}}\) 与量纲转换常数族、\(\kappa\) 多语义、缺口 G5 归属——保持原样并逐处登记。
    5. 物质的量 \(N\)：人为定义的计量量，与自守量纲无关。
    6. 禁用词（根 AGENTS §三）：已删除、已澄清、已修正、已解决、旧版、已废弃、现已统一、早期形式、本版 等过程性表述，不得用于理论文档；本组织层同样避免（负向引用除外）。
    7. 形式化覆盖：F 仅覆盖部分概念（当前 41/82），未覆盖者不得谎报为已形式化。

    六、构建与复现¶

    • 全部产物由 _build/ 脚本从源 CSV 与外部 Lean 源码生成；脚本含断言预检。
    • 执行顺序：fix_csv → build_base → build_evidence → build_claims → build_ontology → build_kg → build_lean → build_ml → build_extract → build_dynamics → build_causal → build_bridge → build_site → build_search → build_reader_site → build_meta。
    • 证据层规则：任何断言都必须能回溯到 00_外部引用/证据映射.csv 的一条记录（含字符区间与引文）；verified 仅人工复核后可置 True。
    • 抽取层规则：术语候选 / 关系候选 / 语义近邻只能进候选池，不得直接写入概念表；抽取只做定位与归一，不推断、不补全。
    • fix_csv.py 为一次性修复脚本（幂等）。
    • 依赖：numpy、networkx、matplotlib、owlready2 + Java（HermiT）、rdflib、pyshacl、jieba、mkdocs-material（阅读站）。
    • 临时工具脚本不得提交；_build/ 不计入产品文件统计。

    七、反模式（明确禁止"忽视维度"）¶

    ❌ 反模式 后果 正确做法
    改了概念表，不重建超图/本体/ML/前端 维度 1–4 失去一致性 依 §四 全链同步
    改了论证表，不更新重写规则与索引 维度 4、2 失真 重跑 build_dynamics、build_ml
    新增 Lean 声明，不更新提取/映射/蓝图 维度 3 与文本脱节 重跑 build_lean
    手工编辑派生的 JSON/OWL/HTML 与源 CSV 分叉、难复现 改源 CSV 后重跑脚本
    产出新结论但不登记元数据 变更不可追溯 更新 11_元数据/
    把缺口/未覆盖写成"已证/已形式化" 违反红线 原样登记

    八、完成判据（自检清单）¶

    • [ ] 变更已落到源 CSV（或 Lean 源码），而非派生文件。
    • [ ] §四 对应行的全部同步脚本已重跑。
    • [ ] check_provenance.py 通过（证据引文与字符区间逐字一致）。
    • [ ] check_consistency.py 通过（退出码 0）。
    • [ ] SHACL 合规且 HermiT 一致；抽取候选只进候选池，未写入概念表。
    • [ ] 缺口编号与状态未被升级；$G_N$ 限定语在位。
    • [ ] 11_元数据/manifest.json 与 变更日志.md 已更新。
    • [ ] 未修改 01–07 理论文档。
