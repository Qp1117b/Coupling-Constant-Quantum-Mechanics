# 理论组织与形式化框架 · 完整设计方案（最终版）

> 六个维度 + 出口层 · 外部文本不动 · Lean 已有只对接 · ML 只做数据准备
> 本文件是 `08 理论组织和形式化框架/` 的顶层设计文档，指导全部子目录的建设与迭代。

## 一、总原则

| 原则 | 说明 |
|:---|:---|
| **外部文本不动** | 理论文本存外部文件夹，项目只存引用、锚点、结构化数据、形式化产物 |
| **六个维度** | 结构化、ML 数据准备、形式化验证、动态机制、经验检验、元理论反思；另设出口层「输出可视化展示」 |
| **混合领域** | 物理+哲学+政治：模块化多范式，不强行统一逻辑 |
| **全部开源/免费** | 主流、专业、社区认可、资料丰富 |
| **Lean 已有** | 不重新形式化，只做对接和反向抽取 |
| **ML 只做数据** | 不训练模型，只转格式 |
| **人看主格式 HTML** | Markdown 写源，HTML 做交互，PDF 存档 |

## 四、各维度详细方案

### 维度 1：结构化

**目标**：将外部理论文本转为机器可读的概念、命题和关系网络。

| 任务 | 工具 | 说明 |
|:---|:---|:---|
| 文本标注 | INCEpTION / doccano | 开源标注工具，自定义标注模式 |
| 论证建模 | Argdown | 简单语法，嵌入 Markdown，生成论证图 |
| 本体构建 | Protégé / Owlready2 | 行业标准，OWL/RDF，HermiT 推理机 |
| 理论图构建 | EpistemeX | 神经符号框架，自动抽取公理、假设、论证关系 |
| 超图构建 | XGI / HyperNetX | Python 超图分析，支持可视化和动力学 |
| 图数据库 | Neo4j Community | 免费图数据库，Cypher 查询 |

**产出**：概念表、命题表、OWL 本体、超图 JSON、理论依赖图、二部图。

### 维度 2：机器学习数据准备

**目标**：将超图和 Lean 代码转成 ML 就绪格式，不训练模型。

| 任务 | 工具 | 说明 |
|:---|:---|:---|
| 超图导出 PyG | PyG | 节点特征+超边索引→`.pt` |
| 超图导出 DGL | DGL | 异构图→`.bin` |
| 超图专用框架 | AllSet | 超图神经网络完整数据准备 |
| 证明数据集 | LeanDojo | 导出 `命题-证明对.jsonl`、`前提-结论对.jsonl` |
| 嵌入就绪 | Markdown | 写清节点特征矩阵、超边索引、推荐嵌入方法 |

**产出**：PyG/DGL 格式文件、节点特征 CSV、证明数据集 JSONL、嵌入就绪文档。

### 维度 3：形式化验证（对接已有 Lean）

**目标**：从已有 Lean 代码反向抽取结构，与结构化数据对接。

| 任务 | 工具 | 说明 |
|:---|:---|:---|
| 记录 Lean 项目 | YAML | 记录路径、版本、模块 |
| 结构提取 | LeanDojo | 提取定义、公理、定理、依赖图 |
| 蓝图属性 | LeanArchitect | `@[blueprint]` 关联 Lean 声明与蓝图节点 |
| 蓝图生成 | leanblueprint | `leanblueprint web` 生成交互式 HTML |
| 概念映射 | CSV | Lean 名称↔概念/命题 ID |

**产出**：Lean 结构提取、Lean↔概念映射、蓝图网页、依赖图。

### 出口层：输出可视化展示

**目标**：交互式、可视化、可讲解、可推进理论。

| 用途 | 工具 | 输出 |
|:---|:---|:---|
| 交互式网站 | Quarto | Markdown→HTML，Mermaid、Lean 高亮、交叉引用 |
| 科学出版 | Curvenote | 连接式出版，实时数据、交互图表 |
| 证明蓝图 | leanblueprint | 可点击的证明依赖网页 |
| 超图交互 | PyVis / Plotly | 可缩放、拖拽、点击的 HTML |
| 理论地图 | Mermaid | 嵌入 Markdown，自动渲染 |
| 概念图 | CmapTools | 手工构建概念关系图 |
| 正式存档 | Quarto→PDF | 论文、报告 |
| 静态图 | Graphviz | SVG/PNG |

**产出**：HTML 网站、蓝图网页、交互式超图、理论地图、讲解文档、报告、PDF。

### 维度 5：动态机制

**目标**：建模理论的结构、概念和命题如何随时间变化、修正和扩展。

| 子方向 | 工具 | 说明 |
|:---|:---|:---|
| 通用动态系统 | PyDSTool | Python 环境，开发、模拟、分析动力系统 |
| 状态空间建模 | C4DYNAMICS | 模块化架构，严格状态定义 |
| 大规模动态系统 | TSdynamics | 177 种内置动力系统，Rust 积分引擎 |
| 认知过程建模 | Procela | 模拟运行时质疑自身假设，建模理论演化 |
| 认知结构变化 | Dynamic Mathematics | 形式化本体框架，描述思想、意义随时间变化 |
| 系统行为引擎 | Carlo | 建模系统移动、变化、稳定、矛盾、生成新结构 |
| 基于规则建模 | Kappa | 构建和交互式探索基于规则的模型 |
| 复杂演化系统 | Utopia | 支持复杂和演化系统全工作流 |
| 多范式建模 | PolyModel | 六种范式：动力系统、元胞自动机、网络、反应式智能体等 |
| 进化动力学 | EvoLudo | 进化过程计算探索和可视化 |

**产出**：演化模型、重写规则、仿真轨迹、动态超图。

### 维度 6：经验检验

**目标**：将理论预测与现实世界数据对接，进行因果推断和假设检验。

| 子方向 | 工具 | 说明 |
|:---|:---|:---|
| 因果推断 | DoWhy | 微软开源，因果假设作为一等公民，测试和验证 |
| 实证研究全流程 | StatsPAI | 800+ 函数，从计量经济学到 ML 因果方法 |
| 贝叶斯网络结构学习 | bnlearn (R) | 结构学习、参数学习、推断 |
| 贝叶斯因果发现 | BCDAG (R) | 高斯 DAG 结构学习和因果效应估计 |
| 实验设计与分析 | experiment-utils-pd | 协变量平衡、回归、IV、AIPW |
| 因果结论 | decisive | 返回因果结论而非数字，告诉你何时不该信任 |
| 贝叶斯网络推理 | pgmpy | 贝叶斯网络算法和工具，模型测试 |
| 贝叶斯网络验证 | BayesL | 形式化指定、查询、验证贝叶斯网络行为 |
| 工具目录 | Auto-Empirical-Research-Skills | 许可和维护状态感知的工具索引 |

**产出**：因果模型、贝叶斯网络、实验设计、检验报告。

### 维度 7：元理论反思

**目标**：形式化理论的本体论、认识论假设和逻辑基础。

| 子方向 | 工具 | 说明 |

| 逻辑统一 | LATIN | 统一形式化数学、逻辑、计算机科学基础语言 |
| 元逻辑框架 | Twelf | 指定、实现、研究演绎系统的元理论 |
| 哲学形式化 | Isabelle/HOL | 已用于形式化形而上学基础和抽象对象理论 |
| 数理逻辑根基 | Lean 4 / Rocq | 机器可核验的数理逻辑根基 |

| 本体论+范畴论推理 | pr4xis (Rust) | 每个断言从明确公理推导，带回溯证明路径 |

**产出**：范畴论模型、类型论基础、哲学假设形式化、元理论报告。

## 九、一句话总结

> **一套方案，六个维度 + 一个出口层，三个核心 + 三个补充：**
> 结构化 → ML 数据准备 → 形式化验证 → 动态机制 → 经验检验 → 元理论反思；出口层：输出可视化展示。
> 外部文本不动，Lean 已有只对接，ML 只做数据准备。
> 全部工具主流、开源、免费、社区认可。
> 人看的主格式是 HTML，Markdown 写源，PDF 存档。
> 先做四个核心，再逐步扩展三个补充。
> 一次建设，多方受益：理论本身、AI、软件、形式化、人本、协作、传播。
