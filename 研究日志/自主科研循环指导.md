# 自主科研循环指导

> 本文档指导 CodeArts Agent 定时执行自主科研循环。定时任务通过 `cronCreate` 创建。

---

## 循环流程（6 步）

### 第 1 步：现状评估
```bash
bash scripts/lean_audit.sh     # Lean 严谨性审计
bash scripts/doc_audit.sh      # 文档一致性审计
bash scripts/repro_check.sh    # 复现性清单检查
```
读取 `附录/缺口台账.md` 了解未闭合缺口状态。

### 第 2 步：方向选择
从缺口台账中按优先级选择研究方向：
- **P0**：恢复可编译基线（修坏导入 + RiemannXi）
- **P1**：SpectralGeometry 全绿
- **P2**：FGChain 收敛
- **P3**：Superconductivity 收敛
- **P4**：缺口公理收敛（axiom → theorem）

或选择一个未验证数值（☯、𝔠₁、$G_N$ 参数、Mathieu 临界 $\lambda_c$ 等）。

### 第 3 步：文献调研
用 MCP 工具检索相关文献：
- `arxiv`：arXiv 文献分节读
- `paper-search`：多源论文检索
- `scholar`：学术搜索
- `gpd-conventions`：物理约定检查

核对项目文档中的引用（Voros/LeClair/Sierra/Tate/Berry–Keating 等）。

### 第 4 步：理论分析
用 MCP 工具做符号计算与数值复核：
- `sympy`：符号计算（☯ 推导、Mathieu 特征值、谱修正 κ）
- `science`：科学计算
- `gpd-verification`：物理验证
- `gpd-patterns`：模式识别

与 `README.md` 数值表比对，偏差须带"构造后验数字校验，待独立复现"。

### 第 5 步：形式化检查
用 `lean` MCP（lean-lsp）检查所选缺口对应的 Lean 模块：
- 诊断编译错误
- `#check` 类型检查
- goal 状态查看
- 定位 `sorry`/`axiom`/`native_decide` 候选

### 第 6 步：报告生成
将本次循环发现写入 `研究日志/YYYY-MM-DD_HHmm_方向.md`：
- 现状评估结果（审计输出摘要）
- 所选缺口/数值及优先级
- 文献调研发现（新引用/引用核对结果）
- 理论分析结果（符号推导/数值复核）
- 形式化状态（编译错误/缺口公理状态）
- 下一步建议（具体可执行动作）

---

## 规则（红线）

1. **不欺骗**：不得用 `axiom`/定义式证明/占位 `def` 冒充已证结论
2. **不绕过**：不得跳过未闭合缺口（C/G2–G8/G9–G22/N1–N4/H3.1–H3.3）
3. **不虚构**：不得引入 CQM 未涉及的观点、术语、数值、文献
4. **数值限定**：凡 $G_N$ 数值须带"构造后验数字校验，待独立复现"
5. **探索无果**：未得出确定结论时不写入理论文档，仅记录到研究日志
6. **术语统一**：发现术语不统一直接按 `附录/术语表.md` 统一替换

## 定时任务配置

| 任务 | 频率 | cron | 说明 |
|:---|:---|:---|:---|
| 全面科研循环 | 每天 09:00 | `0 9 * * *` | 完整 6 步循环 |
| 快速状态检查 | 每 6 小时 | `0 */6 * * *` | 仅第 1+5 步（审计+形式化） |
